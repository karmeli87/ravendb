# RavenDB Endpoints Metadata Export

This directory contains endpoint metadata exported from the RavenDB codebase using the EndpointsExporter tool and RavenDB's native Smuggler export API.

## Files

### endpoints-metadata.json (57KB)
- **Generated by**: TypingsGenerator with EndpointsExporter
- **Format**: JSON array with camelCase keys
- **Content**: All 189 documented GET endpoints with descriptions and query parameters
- **Use case**: Consumption by tools, documentation generators, IDE auto-complete

### endpoints-export.ravendbdump (10KB)
- **Generated by**: RavenDB Server's Smuggler Export API
- **Format**: Zstandard-compressed JSONL (official RavenDB export format)
- **Content**: Complete database export with all 189 endpoint documents
- **Use case**: Direct import into RavenDB Studio or via Smuggler API

### ENDPOINTS-README.md
- This documentation file

## Generation Process

These files were generated using the following process:

1. **Build TypingsGenerator**: The TypingsGenerator tool with EndpointsExporter was built
2. **Generate Metadata**: TypingsGenerator scanned all RavenDB handlers and extracted endpoint metadata into `endpoints-metadata.json`
3. **Start RavenDB Server**: A RavenDB server instance was started
4. **Create Database**: A new database named "EndpointsDB" was created
5. **Insert Documents**: All 189 endpoints from the generated metadata were inserted as documents
6. **Export via Smuggler**: RavenDB's native `/smuggler/export` API was called to create the official export file

This ensures the export file is in the exact format produced by RavenDB itself, not a manually constructed approximation.

## Import Instructions

### Using RavenDB Studio

1. Open RavenDB Studio (http://your-ravendb-server:8080)
2. Create a new database or select an existing one
3. Go to **Settings** → **Import Data**
4. Click **Choose File** and select `endpoints-export.ravendbdump`
5. Click **Import Database**
6. Wait for the import to complete
7. Query the "Endpoints" collection

### Querying Endpoints

After import, use RQL to explore the endpoints:

```javascript
// Get all endpoints
from Endpoints

// Find endpoints with query parameters
from Endpoints where QueryParams.length > 0

// Search by path pattern
from Endpoints where Path like '%index%'

// Filter by handler
from Endpoints where Handler = 'IndexHandler'

// Find by HTTP method
from Endpoints where Method = 'GET'

// Complex query
from Endpoints 
where Path like '%stats%' and QueryParams.length > 0
```

## Metadata Structure

Each endpoint document has the following structure:

```json
{
  "@metadata": {
    "@collection": "Endpoints",
    "@id": "endpoints/1"
  },
  "Path": "/databases/*/indexes/terms",
  "Method": "GET",
  "Description": "Returns all terms in a specified index field...",
  "Handler": "IndexHandler",
  "MethodName": "Terms",
  "QueryParams": [
    {
      "Name": "name",
      "Required": true,
      "Description": "The name of the index.",
      "Type": "string",
      "DefaultValue": null
    }
  ]
}
```

## Notes

- The export file uses **Zstandard compression** (`.zst`), which is the official format used by RavenDB's Smuggler
- The export was created by RavenDB's own export API, ensuring compatibility and correctness
- All metadata comes directly from the codebase via reflection on `RavenActionAttribute` and `RavenActionQueryParameterAttribute`
- The endpoints-metadata.json file uses camelCase for JavaScript/TypeScript compatibility
- The RavenDB documents use PascalCase following C# conventions
